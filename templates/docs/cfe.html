Modulo CFE — Vision General

Implementado en junio 2026. Descarga automatica de recibos XML y PDF del portal CFE para todos los servicios registrados.

Por que existe

Los clientes de O&M tienen contratos de monitoreo que requieren validar consumos contra la facturacion de CFE. El modulo automatiza la descarga de recibos (XML oficial + PDF) para todos los servicios registrados, evitando la descarga manual mes a mes.

Flujo de datos

1

Registro de servicio CFE

El usuario registra el numero de servicio (RPU). El sistema verifica que exista en el portal publico de CFE y obtiene el nombre del titular.

2

Alta en MiEspacio CFE

El Worker registra el servicio en la cuenta MiEspacio de Enertika. Requiere el total del ultimo recibo como verificacion. Este paso es independiente de la descarga.

3

Descarga periodica automatica

El Worker revisa periodicamente si hay periodos nuevos. Descarga XML del portal publico y PDF desde MiEspacio > Otras Facturas. Los archivos se guardan en SharePoint.

4

Consulta y analisis

Los usuarios pueden consultar el historico de recibos, descargar ZIP (XML + PDF + Excel), y ver el analisis de perfil tarifario (GDMTH/GDMTO) por servicio.

Componentes

Backend (Railway)

  • modules/cfe/scraper.py — Playwright headless
  • modules/cfe/service.py — logica de negocio y jobs
  • modules/cfe/analysis.py — KPIs y perfil tarifario
  • worker.py — jobs periodicos de descarga

Infraestructura externa

  • pproxy — PC de oficina, puerto 3128, IP publica estatica
  • SharePoint — almacenamiento de XML y PDF
  • app.cfe.mx — portal publico (XML) y MiEspacio (PDF)

Limitacion critica

Railway corre en AWS. CFE bloquea IPs de datacenters silenciosamente (sin respuesta HTTP, la conexion simplemente expira). Por eso todo el trafico del scraper pasa por el proxy pproxy instalado en la oficina, que sale con la IP publica estatica contratada de Enertika.

Proxy pproxy — Configuracion Completa

Proxy HTTP instalado en la PC de oficina. Implementado el 11 de junio 2026. Herramienta confirmada: pproxy 2.7.9 (python-proxy).

Donde esta instalado

Maquina

PC de oficina (Windows) — la misma que tiene IP publica estatica asignada por el ISP

Ejecutable

C:\Users\ENERTIKA\AppData\Local\Programs\Python\Python313\python.exe

El proxy se levanta como modulo Python: -m pproxy.

Puerto

3128 (HTTP proxy estandar)

Modo de inicio

Tarea programada CfeProxy, con desencadenador Al iniciar el sistema.

Accion configurada en la tarea CfeProxy

Programa:
C:\Users\ENERTIKA\AppData\Local\Programs\Python\Python313\python.exe

Argumentos:
-m pproxy -l "http://0.0.0.0:3128#cfe:<PASSWORD>"

Notas de la accion

  • -m pproxy — ejecuta el modulo instalado en Python 3.13.
  • 0.0.0.0:3128 — escucha en todas las interfaces de red de la PC.
  • #cfe:<PASSWORD> — credenciales HTTP del proxy. La contrasena real esta en la tarea y en Railway, no en este documento.
  • Se confirmo con pip show pproxy que la version instalada es 2.7.9.

Variable de entorno en Railway

Worker → Variables

CFE_PROXY_URL=http://cfe:<PASSWORD>@<IP_PUBLICA_OFICINA>:3128

Esta variable esta configurada SOLO en el servicio Worker (no en el app principal). Si no existe o esta vacia, el scraper corre sin proxy y CFE bloquea la conexion.

Configuracion de red

Router de oficina

Port-forward TCP puerto 3128 externo → IP local de la PC con pproxy, puerto 3128 interno.

Firewall de Windows

Regla de entrada habilitada para TCP 3128. Nombre sugerido de regla: CfeProxy.

netsh advfirewall firewall add rule name="CfeProxy" dir=in action=allow protocol=TCP localport=3128

Auto-inicio y recuperacion

Estado actual en produccion: tarea programada

# Ver estado
Get-ScheduledTask -TaskName "CfeProxy" | Select-Object TaskName, State

# Ver accion configurada
Get-ScheduledTask -TaskName "CfeProxy" | Select-Object -ExpandProperty Actions

# Iniciar manualmente
Start-ScheduledTask -TaskName "CfeProxy"

Limitacion de la tarea programada

La tarea programada puede arrancar al iniciar Windows si esta configurada como Ejecutar tanto si el usuario inicio sesion como si no, pero no es tan buena como un servicio para recuperarse de caidas. Puede quedar en estado ambiguo si el proceso Python termina, si falta la contrasena guardada o si el reinicio ocurre antes de que la red este lista.

NSSM

Envuelve un programa de consola como servicio de Windows. Es la opcion mas directa para python.exe -m pproxy: auto-inicio, reinicio al fallar y logs de salida/error.

nssm install CfeProxy "C:\Users\ENERTIKA\AppData\Local\Programs\Python\Python313\python.exe"
nssm set CfeProxy AppParameters -m pproxy -l "http://0.0.0.0:3128#cfe:<PASSWORD>"
nssm set CfeProxy AppStdout C:\CfeProxy\logs\stdout.log
nssm set CfeProxy AppStderr C:\CfeProxy\logs\stderr.log
nssm set CfeProxy Start SERVICE_AUTO_START
nssm start CfeProxy

WinSW

Hace lo mismo que NSSM, pero con un archivo XML junto al ejecutable. Conviene si se quiere versionar la configuracion del servicio y reinstalarla de forma repetible.

<service>
  <id>CfeProxy</id>
  <name>CfeProxy</name>
  <description>Proxy CFE via pproxy</description>
  <executable>C:\Users\ENERTIKA\AppData\Local\Programs\Python\Python313\python.exe</executable>
  <arguments>-m pproxy -l "http://0.0.0.0:3128#cfe:<PASSWORD>"</arguments>
  <startmode>Automatic</startmode>
  <onfailure action="restart" delay="60 sec"/>
</service>

sc.exe

sc create registra servicios nativos de Windows. No es ideal para ejecutar directamente python.exe -m pproxy, porque Python no implementa el protocolo del Service Control Manager. Para pproxy se recomienda NSSM o WinSW antes que sc.exe.

Por que seria mejor que la tarea

Un servicio puede iniciar antes de iniciar sesion, reiniciarse automaticamente si el proceso falla, escribir logs persistentes y consultarse con Get-Service CfeProxy. Reduce la intervencion manual cuando el equipo se reinicia fuera de oficina.

Scraper CFE — Como funciona

Playwright (Python, headless Chromium) que navega el portal CFE. Archivo: modules/cfe/scraper.py

Dos portales, dos flujos

Portal Publico

app.cfe.mx — ReciboDeLuzGMX

  • No requiere sesion
  • Devuelve XML oficial con el consumo
  • Se usa para alta (obtener total del ultimo recibo) y para descarga de XML
  • Sujeto a bloqueo por IP de datacenter

MiEspacio

app.cfe.mx — MiEspacio

  • Requiere sesion activa (cookie guardada)
  • Acceso a Otras Facturas: XML + PDF historicos
  • Permite registrar servicios en la cuenta de Enertika
  • La sesion expira periodicamente — requiere renovacion manual

Como se aplica el proxy al scraper

La funcion _build_proxy_kwargs() en scraper.py:37 lee CFE_PROXY_URL del entorno y construye los kwargs de Playwright:

def _build_proxy_kwargs() -> dict:
    raw = os.environ.get("CFE_PROXY_URL", "").strip()
    if not raw:
        return {}   # sin proxy — CFE bloqueara la conexion
    parsed = urlparse(raw)
    proxy = {"server": f"{parsed.scheme}://{parsed.hostname}:{parsed.port}"}
    if parsed.username:
        proxy["username"] = parsed.username
    if parsed.password:
        proxy["password"] = parsed.password
    return {"proxy": proxy}

Se aplica en _chromium_launch_kwargs() que es llamado por todos los flujos (portal publico, MiEspacio y alta). El proxy opera a nivel del browser, no del contexto, por lo que aplica a todas las navegaciones.

Deteccion de bloqueo

La funcion _detect_block(page) analiza el HTML cargado y detecta:

Imperva/Incapsula

Bloqueo activo — CFE devuelve pagina con contenido de seguridad

Pagina vacia

body_html_len menor 600 bytes y sin titulo — bloqueo silencioso por IP de datacenter (la pagina carga pero sin contenido)

ERR_TIMED_OUT

La conexion TCP nunca completo. Ocurre cuando el proxy esta caido o no configurado. _detect_block nunca llega a ejecutarse porque goto() ya expiro.

Nota sobre el log ERR_TIMED_OUT

Cuando el Worker muestra net::ERR_TIMED_OUT en el log CFE, la causa mas probable es que el proxy de oficina no estaba corriendo al momento del intento. No indica un problema con el codigo ni con Railway. Verificar primero la tarea CfeProxy, el proceso python.exe -m pproxy y el puerto 3128 en la PC de oficina.

Operacion y Diagnostico

Procedimientos para verificar el estado del sistema, diagnosticar errores y recuperar el servicio.

Checklist de verificacion rapida

1

Verificar que pproxy esta corriendo

Get-ScheduledTask -TaskName "CfeProxy" | Select-Object TaskName, State
netstat -ano | findstr :3128

Esperado: tarea Running y puerto LISTENING. Si no aparece, ver Paso 2.

2

Iniciar la tarea manualmente

Start-ScheduledTask -TaskName "CfeProxy"

Despues de iniciarla, repetir el Paso 1 y confirmar que el puerto 3128 quedo escuchando.

3

Confirmar que el puerto es accesible desde internet

telnet <IP_PUBLICA_OFICINA> 3128

Debe conectar (pantalla en negro). Si no conecta: verificar port-forward en el router y la regla del firewall de Windows.

4

Verificar la variable en Railway Worker

Railway → proyecto → servicio Worker → Variables → buscar CFE_PROXY_URL. Debe existir con el formato http://cfe:PASS@IP:3128.

5

Confirmar en logs del Worker que el proxy esta activo

[CFE] Usando proxy http://<hostname>:3128

Esta linea aparece en cada descarga si CFE_PROXY_URL esta configurada. Si no aparece, la variable no llega al Worker.

Errores comunes y su causa

Mensaje en log Causa Accion
net::ERR_TIMED_OUT pproxy no esta corriendo, el puerto 3128 no escucha o fallo el port-forward/firewall Start-ScheduledTask -TaskName "CfeProxy" y validar netstat en la PC de oficina
Portal CFE devolvio pagina vacia IP de datacenter bloqueada — el proxy no estaba activo o CFE cambio sus reglas Verificar proxy. Si el proxy esta activo pero el error persiste, CFE puede estar bloqueando la IP de la oficina temporalmente.
Portal CFE bloqueado por Imperva Demasiadas solicitudes en poco tiempo desde la misma IP Esperar 15-30 minutos. El bloqueo de Imperva es temporal.
La sesion CFE MiEspacio expiro La cookie de sesion de MiEspacio venco Renovar sesion desde Admin > Configuracion Global > Recibos CFE
El servicio no esta registrado en MiEspacio El alta automatica no se completo aun o fallo Forzar alta manual desde la lista de servicios CFE

MiEspacio CFE — Sesion y Alta de Servicios

MiEspacio es la cuenta de Enertika en el portal CFE. Permite descargar facturas historicas (XML + PDF) y registrar servicios de clientes.

Sesion de MiEspacio

La sesion se guarda como JSON de cookies (storage state de Playwright) en la base de datos, campo tb_configuracion_global con clave cfe.session_json.

Duracion de la sesion

Variable — CFE puede expirarla en dias o semanas. No hay notificacion automatica de expiracion.

Como renovar

Admin → Configuracion Global → Recibos CFE → boton Renovar Sesion. Requiere correr el lanzador local renovar_sesion.py desde una PC de la oficina (necesita acceso interactivo para resolver CAPTCHA).

Alta de servicios en MiEspacio

Cuando se agrega un servicio CFE, el Worker debe registrarlo en la cuenta MiEspacio de Enertika. CFE requiere el total del ultimo recibo como verificacion de identidad del servicio.

A

Alta automatica

El Worker extrae el total del ultimo recibo desde el portal publico (XML) y lo usa para registrar el servicio automaticamente.

M

Alta manual (cuando falla la automatica)

Si el portal publico no tiene el recibo o el total no coincide, el usuario puede ingresar el total manualmente desde el popup de error en la lista de servicios.

Herramientas locales (correr en PC de oficina)

tools/cfe/renovar_sesion.py

Abre Edge de forma interactiva para que el usuario inicie sesion en MiEspacio y resuelva el CAPTCHA. Guarda las cookies en la BD automaticamente.

tools/cfe/alta_asistida.py

Alta supervisada paso a paso. Pausa antes de cada "Guardar" para revision humana. Util cuando el alta automatica falla repetidamente.

tools/cfe/volcar_dom.py

Captura el DOM real de las paginas de MiEspacio (AgregarServicio.aspx, Default.aspx) para diagnosticar cambios de selectores cuando el alta falla.

Por que las herramientas locales evitan el proxy

Estas herramientas corren en la PC de la oficina, que ya tiene la IP publica estatica. Por eso no necesitan pasar por pproxy — salen directamente con la IP de confianza de Enertika. El scraper del Worker en Railway sí necesita el proxy porque Railway usa IPs de AWS que CFE bloquea.
